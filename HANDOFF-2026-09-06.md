## What is in the nine commits

### 1. Fire TV detection (`68dce13`)

`\baft[bmnst]\b` only matched `AFTB`/`AFTM`/`AFTN`/`AFTS`/`AFTT` — no real
device. Actual codes are `AFTKA`, `AFTMM`, `AFTSSS`, `AFTKMST12`. Widened to
`\bAFT[A-Z0-9]{1,10}\b`.

**The missing `/i` is load-bearing** — it is the only thing separating a device
code from the word "after", since Amazon writes codes uppercase and prose does
not. `src/lib/tv-user-agent.test.ts` fails if anyone adds it back; that was
verified by actually adding it and watching it fail.

### 2. Offline downloads — phone, tablet, Windows (`2339dee`, `ed54016`, `ec9ea44`, `2f814d5`)

A download is a **bundle**: media + every text subtitle + poster + a manifest.
Subtitles are the reason — they are not beside the video, Jellyfin renders each
to WebVTT on demand, so a client pulling only the media gets a film nobody can
read. They are tens of KB, so there is no case for making anyone choose.

- **Server**: `/api/download/:id/manifest` describes the bundle. It does not
  queue a prepare job — asking what a download contains should not start
  producing one.
- **Range support already existed** but answered 416 where the spec says clamp,
  so a resuming downloader was told the file was gone and started over. Now in
  `src/lib/http-range.ts` with 11 tests.
- **Android**: a Capacitor plugin; media via the system `DownloadManager`
  (survives backgrounding, resumes, survives the screen locking).
- **Windows**: a Rust mirror; streams to `media.part` and only renames when
  complete, so a half-file cannot look ready.
- **Service worker** moved from `public/sw.js` to `src/app/sw.js/route.ts` so
  its cache name carries Next's `BUILD_ID`. The old constant was both the
  version marker and the only purge trigger — a rule nobody keeps.

**Four traps, each of which would have shipped silently:**

| Trap | Why it matters |
| --- | --- |
| `<track>` is CORS-checked, `<video>` is not | Local files are a different origin, so subtitles load nothing with no error. They go through `readText()` and become `blob:` URLs. |
| `cache.addAll` is all-or-nothing **and rejects redirects** | Precaching `/downloads` while logged out fails the install → **no service worker at all**. Hence `/downloads` is excluded from auth middleware. |
| `cookies_for_url` deadlocks on Windows in sync Tauri commands | Documented, and Windows is the only platform that app ships on. Every command in `offline.rs` is `async`. |
| Session cookie is httpOnly | JS cannot hand it to the native side even deliberately; each shell reads its own cookie jar. |

**Rule for version skew:** playback of an existing bundle is **never** gated on
the bridge version. Only management degrades, with a notice — that needs a
network anyway, so it is actionable.

### 3. Special features (`10ea826`, `368993e`, `b2a6d10`, `6c77e34`, `b46182a`)

Making-ofs, documentaries about a director, retrospectives on an actor —
library items that are ABOUT something rather than the thing you sat down to
watch.

- **Marking hides from discovery and nothing else.** It keeps its own page and
  stays playable, because `filterVisible()` already drew that line — it gates
  discovery and is deliberately not applied to `getItem()`. Continue Watching
  passes `includeSpecialFeatures`, the one row they are allowed into.
- **Marking and mapping are separate tables** because they happen at different
  times. An unmapped feature is a real state, not a mistake.
- **A franchise IS a library group** (`kind: "movie"`), so `/collection/[id]`
  was already the franchise page — no second concept.
- Surfaces on film, person and franchise pages, most-specific-first, each
  labelled with why it is there.
- **The guesser proposes and never applies.** Deliberately reluctant: the word
  "documentary" alone stays under the bar, because the worst outcome is hiding
  a real documentary somebody meant to watch. Titles match whole (not
  substrings — "Alien" would map half the library) and one-word names are never
  proposed.
- **Console lives in the Library workspace, not its own tab** — "hide from the
  site" and "special feature" are the same question. An unconfirmed suggestion
  flows into the existing **"Needs you"** chip rather than a second queue.
- Selecting a film lists what hangs off it, distinguishing **direct from
  inherited**: unlinking a director mapping removes it from *every* film by
  that director, so those render dashed and the confirm says so.

Schema went **41 → 42** (two new tables, no ALTER; both sides were on 41, no
collision).
